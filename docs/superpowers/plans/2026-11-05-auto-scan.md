# 全自动扫描 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标:** 选人阶段不用按热键,程序自己发现画面变化、重新识别、刷新推荐;轮到我时推荐不乱跳;游戏里不卡。

**做法:** 把「什么时候扫」「画面变没变」「推荐要不要推」做成 `core` 里三个纯逻辑小件(用假时钟、假数据测),`app` 里加一个自动扫描循环把它们和现有的 `scan()`、GSI、托盘接起来。截图默认改用画面流(先验证识别结果一致)。

**技术栈:** TypeScript · Electron 31 · Vitest · koffi(只读 Win32 查询)

**设计文档:** [docs/superpowers/specs/2026-11-05-auto-scan-design.md](../specs/2026-11-05-auto-scan-design.md)(实现者两份都要读)

## 全局约束

- 只读屏幕:不读内存、不注入、不模拟输入;Win32 写操作只能对自己的悬浮窗。新加的 Win32 调用只能是查询(`GetForegroundWindow`),`npm run compliance` 必须通过。
- 开了 GSI 时,只在 `DOTA_GAMERULES_STATE_INIT` / `DOTA_GAMERULES_STATE_WAIT_FOR_PLAYERS_TO_LOAD` / `DOTA_GAMERULES_STATE_HERO_SELECTION` 截图;其他阶段一张不截。
- 没开 GSI(或 GSI 超过 30 秒没数据):Dota 窗口在时每 3000ms 轻量查看一次;进入选人后约每 1000ms 取一帧;连续 2 次不是选人界面退回 3000ms 查看。
- Dota 窗口不在:不截图。Dota 不在最前面:这一帧跳过,不计入任何「不是选人界面」的计数。
- 画面变化比较区域**不得**包含倒计时(中央倒计时、玩家卡倒计时徽章)、闪烁边框;比较区域只取识别区域(池格、英雄格、卡上已选格)。
- 画面变化后等静止再识别;超过 3000ms 仍不静止就照样识别一次。
- 轮到我:本回合首次刷新后锁住;若首次读数不完整,允许之后第一次完整读数再刷新一次,然后锁死;我的卡多一格或明确轮到别人才解锁;`activeRow` 读成 null 不解锁;`myRow` 为 null 不锁;热键扫描不受锁限制。
- 托盘「自动扫描」勾选项默认开,设置持久化。没开 GSI 时托盘提示「启用 GSI 可以省掉游戏里的截图开销」。
- 存帧只在真正跑了识别时存;按局分文件夹,只留最近 5 局。
- 不改识别逻辑和阈值,不改打分。

## 重点审查

计划里各任务的测试没直接覆盖、但最可能让用户碰上的情况(每条的测试已加到对应任务里):

1. 选人中途切到别的窗口再切回来 → 自动扫描不停、悬浮窗不藏,切回来马上接着扫(任务 3、任务 7)。
2. 程序在选人进行到一半时才启动、或 GSI 中途断了 → 3 秒内进入选人扫描,不需要按热键(任务 3)。
3. 热键和自动扫描撞在一起 → 不会同时跑两次识别,热键那次不被丢掉(任务 7)。
4. 轮到我时鼠标一直在池子上晃 → 3 秒内照样出推荐,而不是一直显示上一手的(任务 2、任务 7)。
5. Dota 选人中途被关掉 → 立刻停止截图,不报错刷屏(任务 3、任务 7)。
