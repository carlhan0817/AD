# 第二阶段:让推荐认识「你」(大白话版)

日期:2026-10-27(夜里离线完成,待真机测试)

## 做了什么

之前的推荐不知道你是谁、选了什么、选到第几手,只能按技能本身的胜率排,分数都在 0.15 左右。
这一轮让程序在每次扫描时顺便读一遍两侧的玩家卡:

| 读什么 | 怎么认 | 在你存下的 19 张真帧上的结果 |
|---|---|---|
| 你坐哪张卡 | 你的卡有一圈绿色外框(坐左列在左边缘、坐右列在右边缘) | 全对(左1、右4 两个座位都验证过) |
| 现在轮到谁 | 那张卡变成金色底 | 全对 |
| 你已经选了哪些技能 | 卡上 4 个小格,用认技能池的同一个模型认 | 全对;5 帧里卡上认出的技能和池里变空的格完全一致 |
| 英雄被选走 | 模型格变灰:饱和度 < 11 且对比度 < 35;后来明显是彩色(饱和度 ≥ 14)就撤销误判 | 全对 |
| 你选了哪个英雄 | 你卡上的头像和英雄立绘比对,只在本局已被选走的英雄里找 | 全对(Naga、变体精灵);还没选时正确地判为没选 |
| 现在第几手 | 已被选走的技能数 + 英雄数 + 1(共 50 手、5 轮,zigzag 顺序,英雄也算一手) | 和画面对得上(坐第一个选时落在第 21、40 手) |

一局里你坐哪、你选的英雄,认出过一次就记住。

推荐因此有了变化:
- 你已经有大招了,就不再推荐大招;普通技能选满 3 个就不再推荐普通技能;选了英雄就不再推荐英雄;全选满时显示「已选满」。
- 「选位」信号开始起作用:平时第几手会被抢走的技能,到了那个时候会被提前推荐。
- **技能和英雄分开推荐**:技能取前 3 个,英雄(你还没选时)单独给最好的 1 个。
  原因:英雄在数据里没有「平均第几手被选走」,混在一起排时第 1 手会全是英雄。

## 顺带修的

- **说明框不再「复活」已选走的格子**:一格一旦变空就一直算空,英雄一旦变灰就一直算被选走。
- **悬浮窗挪到右下角**:原来在右上角,会盖住右边第一张玩家卡,读不了那张卡。现在在右列最后一张卡下方的空地方,
  并且多了一行状态:你的位置、第几手、是否轮到你、你的英雄。
- **截图快一点**:不再先压成 PNG 再解开,每次省约 80ms,像素完全一样。
- **可选的快速截图**:设 `AD_STREAM_CAPTURE=1` 后改用持续画面流,每次约 50ms(原来 0.03–1.4 秒不等)。
  但画面流的颜色和直接截图有小差异,判空等分界线没在它上面验证过,所以默认不开。

## 打分机制(2026-11-02 用户确定)

权重都在仓库根的 `scoring_config.json`,改完存盘,下一次扫描就生效,不用重启,也不用改代码。

- `roundWeights.base`:第 1~5 轮单技能/英雄强度的权重,逐轮递减。
- `roundWeights.synergy`:第 1~5 轮搭配的权重,逐轮上升。
- `synergyTopN`:搭配分只取已选里最配的几件求平均(默认 2),配得差的已选件不再稀释配得好的。
- 所有按轮次的表都是逐手过渡:5 个数是每轮第一手的值,中间线性变化,轮次交界不跳变。
- `seatBaseBonus`:选位修正(预留,默认 0)。第一个选的人单技能权重乘 (1+该值),第十个不变,中间线性。
- `pairFallback`:搭配数据缺失时的估分比例。`single` 是单技能强度,`similar` 是同类技能和你已选技能的搭配。
- `roundWeights.aghs` / `roundWeights.shard`:第 1~5 轮神杖、魔晶绑定的权重。
- `aghsBinding`:神杖、魔晶绑定的参数,见下。
- `baseWeights.pos`(选位稀缺)目前是 0,想启用就改成非 0。

神杖、魔晶项的算法:

```text
S_aghs(c)  = max(0, scepterGain(c) − aghsBaseline)   # 技能没有神杖升级则为 0
S_shard(c) = max(0, shardGain(c)  − shardBaseline)   # 技能没有魔晶升级则为 0
N_aghs / N_shard = 已选的技能和英雄里,S ≥ bindMin 的个数

神杖项 = W_aghs[r]  × S_aghs(c)  × (1 + aghsStackBonus  × min(N_aghs,  stackCap))
魔晶项 = W_shard[r] × S_shard(c) × (1 + shardStackBonus × min(N_shard, stackCap))
```

要减基准,是因为几乎所有技能买了神杖胜率都更高(中位数 +7.4%,魔晶 +5.0%),这主要反映「买得起的局本来就优势」。

搭配数据缺失时不再算 0:按用户的判断,强势组合总被别人拆开选走,所以样本少。这时改用单技能强度和同类技能估分。
同类技能来自 `models/tags/ability_tags.json`(源自 ability-draft-plus,其中控制类标签源自 Liquipedia,CC-BY-SA 3.0)。

数值都是占位的起点,由用户凭实战手感调整。不做回测:程序运行在玩家本地,拿不到玩家的实战数据。
