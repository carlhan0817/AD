来源截图:`docs/screenshot/20260608235138_1.jpg`(2026-06-08,1920×1080 等比)
用途:下一阶段 ROI 标定 / 状态机行映射 / overlay 渲染的真实依据。
**⚠️ 此前计划书与代码里的若干假设与真实布局不符,以本笔记为准。**

## 设计基准决策(2026-06-09 修正版)

> ⚠️ 本节此前写"独占全屏为唯一基准、不考虑无边框 workaround",**已作废**。合规与技术复核后改为下述基准。完整合规边界见 `docs/compliance/technical-behavior-and-anticheat.md`。

**运行基准 = 无边框窗口(Borderless Window)**——标准透明 overlay 在无边框下能正常盖上(走 DWM 合成),Dota2 现已默认推荐无边框,玩家接受度高。

技术含义(下一阶段):
- 截屏用 **DXGI Desktop Duplication**(`screenshot-desktop` 在全屏下常截黑屏);overlay 定位用 koffi 调 user32 **只读** `FindWindowW`/`GetClientRect`/`ClientToScreen`。
- koffi 写操作(`SetWindowPos`/`SetWindowLong` / `WS_EX_LAYERED|TRANSPARENT`)**仅作用于自身 overlay HWND**;**绝不修改 Dota2 游戏窗口**(合规红线)。
- **真·独占全屏不硬扛**:GPU 直送显示器跳过 DWM,标准 overlay 物理盖不住,强盖会 Z-Fighting 闪烁。改为**只读检测显示模式 → UI 温和提示用户切【无边框窗口】**,不做窗口强攻。
- 下一阶段优先打通"无边框下 DXGI 截屏 + overlay 能盖上"物理链路,再接识别/打分。

## 关键纠正(影响 ROI 与状态机)

| 此前假设(代码/计划书) | 真实情况 |
|---|---|
| 十名玩家排成**垂直十行** | ❌ 实为**左 5 + 右 5 两列**布局,左列红队、右列绿队,每列 5 张玩家卡片 |
| 技能池是单一网格 | ✅ 但明确分**两区**:上方「终极技能」(带绿色高亮框,约 2 行)+ 下方「标准技能」(多行),与 `isUltimate` 对应,可视区已自带分区 |
| Active Picker 是高亮边框 | ✅ **证实**:顶部头像条上当前选人有**绿色高亮框**;中央文字「即将轮到你:103」给出顺位与倒计时 |
| 英雄槽在玩家行内 | ✅ 每张玩家卡片左侧有英雄头像位(截图中均为「无英雄」),其右是该玩家已选技能空格 |

## 布局要素与大致位置(待精确标定)

- **顶部头像条**:横贯顶部,展示全部待抽英雄/技能缩略;当前活动者绿框高亮 = Active Picker 真相来源。
- **中央倒计时**:顶部正中大号数字(截图为「103」),全局回合倒计时。
- **技能池(中央)**:
  - 「终极技能」区:上方,绿色边框圈起,约 2 行。
  - 「标准技能」区:下方,文字「标准技能」标注,多行网格。
- **玩家卡片(左 5 + 右 5)**:
  - 左列(红队,自上而下):MoneyBagZ / Kenny / One for All / Hoodratt / Carpe Diem
  - 右列(绿队,自上而下):RabbitDestroyer / Grapestone / cream / amay / 少爺与志�880(示例局名)
  - 每张卡片:左 = 英雄头像位 + 名牌;右 = 该玩家技能槽(空格)。
  - 部分待选卡片右上角有独立小数字(2、3)= 该位的局部计时/顺位提示。
- **底部**:操作提示文字 + 队伍聊天输入框。

## 对后续工作的影响

1. **ROI 坐标**:`LAYOUT_1080P` / `deriveLayout` 当前按"十行"设想,需按"两列各 5 + 中央双区技能池 + 顶部头像条 + 中央计时"重定坐标。
2. **状态机行映射**:玩家索引 0..9 需映射到「左列 0-4 / 右列 5-9」(或按队伍),而非单纯垂直十行。
3. **终极/标准分区**:识别时可先用可视分区辅助,再以 `isUltimate` 查表确认槽位类型。
4. **Active Picker**:顶部头像条的绿框是顺位权威源,模板/颜色匹配即可,无需 NN。
