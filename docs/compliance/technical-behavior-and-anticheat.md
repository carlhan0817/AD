# AD 助手 — 技术行为说明书 & 反作弊合规边界

> 版本:2026-06-09
> 用途:逐条列出本助手对游戏进程/窗口/系统做的每一个动作及其影响,供与 Valve/Dota2 官方反作弊规则**逐行核对**。
> 关联记忆:`fullscreen-design-baseline`、`koffi-write-only-on-own-hwnd`。
>
> ⚠️ 免责:技术合规 ≠ 政策允许。本文档只陈述技术事实与自评,**最终是否封号以 Valve 官方条款与执行为准**。

---

## 0. 一句话定性

本助手是一个 **screen-reading overlay(读屏覆盖层)**:
- **输入端**:只看屏幕画面(等同截图),**不读游戏内部状态**。
- **输出端**:在**自己的独立窗口**显示信息,**不改游戏画面、不改游戏数据**。
- **对游戏的输入**:**零**。不模拟键鼠、不自动操作、不发送任何消息给游戏。

与外挂(读内存 / 注入 / 自动化)有本质区别。

---

## 1. 全程对 Dota2 进程的关系:只读 + 不接触

| 维度 | 本助手行为 |
|---|---|
| 游戏进程内存 | ❌ 从不读、从不写 |
| 进程注入 / DLL 注入 | ❌ 从不 |
| Hook 游戏渲染(D3D `Present`/`SwapBuffers`) | ❌ 从不 |
| 向游戏窗口发消息 / 模拟输入 | ❌ 从不(零输入) |
| 修改游戏文件 / 客户端 | ❌ 从不 |
| 读取游戏窗口**几何信息**(位置/尺寸) | ✅ 通过系统公开 API 只读 |
| 截取**屏幕画面** | ✅ 系统级截图,与 OBS/Win+PrtSc 同类 |

## 2. 四个技术模块 — 逐个 API 标注

### 2.1 截屏(DXGI Desktop Duplication)
- **API**:DXGI Desktop Duplication(`IDXGIOutputDuplication`)。
- **做什么**:抓**显卡合成后的整屏最终画面帧**,得到位图。
- **对游戏的影响**:**无任何交互**——不附加进程、不读内存、不 hook 渲染。等价于系统级截图(OBS / NVIDIA 录屏 / 直播软件同一类机制)。
- **为何不用 `screenshot-desktop`**:其底层 GDI 在全屏下常截黑屏;DXGI 是只读屏幕帧的稳定路径。
- **合规自评**:✅ 抓屏本身几乎所有反作弊都允许(否则会误伤直播/录屏/截图工具)。

### 2.2 找游戏窗口位置(koffi → user32.dll,**全程只读**)
- **API**:`FindWindowW("Dota 2")` → `GetClientRect(hwnd, ...)` → `ClientToScreen(hwnd, ...)`。
- **做什么**:问操作系统"Dota2 窗口在屏幕哪、多大",得到物理像素(给截屏裁剪)+ 逻辑像素(给 overlay 定位)。
- **对游戏的影响**:**只查询,不修改**。这是任务管理器/截图软件/输入法都在用的公开窗口管理 API。
- **Dota2 HWND 的唯一用途**:作为**只读参数**喂给 `GetClientRect`/`ClientToScreen`,读完即弃。
- **合规自评**:✅ 只读几何查询,不构成干预。

### 2.3 识别 + 打分(本地 ML 推理)
- **做什么**:把截到的图喂本地图像识别模型,认出技能/英雄,在**自建数据库**查胜率/评分。
- **对游戏的影响**:**无**。纯离线、本地、读图;数据来自我们自抓的网络数据,不触碰游戏。
- **合规自评**:✅ 技术层面干净。⚠️ 见 §4「灰色地带」。

### 2.4 覆盖显示(Electron 透明窗口 + koffi 兜底,**写操作只改自己**)
- **做什么**:独立进程的透明、无边框、点击穿透(`setIgnoreMouseEvents(true,{forward:true})`)Electron 窗口,`setAlwaysOnTop(true,'screen-saver')` 浮在游戏画面上方显示评分。
- **koffi 兜底**:必要时对**自身 overlay 的 HWND** 调 `SetWindowPos`(拔 Z 序到 `HWND_TOPMOST`)、`SetWindowLong`(设自己的 `WS_EX_LAYERED`/`WS_EX_TRANSPARENT`)。
- **对游戏的影响**:**无**。overlay 是独立窗口,只是视觉上浮在上方,**不进入游戏渲染管线**。与 Discord 覆盖 / 输入法候选框同性质。
- **🚫 硬性红线**:Win32 **写操作**(`SetWindowPos`/`SetWindowLong`/`SetWindowDisplayAffinity`/`SendMessage`/`ShowWindow` 等)**只能作用于自身 overlay HWND,绝不能传入 Dota2 HWND**。

## 3. 显示模式策略:无边框为基准,独占全屏只读检测 + 引导

| 显示模式 | overlay 能否盖上 | 本助手做法 |
|---|---|---|
| **无边框窗口(Borderless)** | ✅ 走 DWM 合成,标准透明 overlay 能盖 | **运行基准**,正常工作 |
| 真·独占全屏(Exclusive Fullscreen) | ❌ GPU 直送显示器、跳过 DWM,强盖会 Z-Fighting 闪烁 | **只读检测显示模式 → UI 温和提示用户切【无边框窗口】**;**绝不技术强攻** |

**为何不强攻独占全屏**:既有技术现实障碍(DWM 旁路),又有合规风险——若用 `SetWindowLong` 去强改 Dota2 窗口样式/剥夺独占属性,即构成"外部干预客户端状态",可致游戏撕裂/黑屏/崩溃,Crash Dump 回传 Valve 可能触发人工审查。**技术上能做,合规上主动不做。**

## 4. 与官方反作弊规则对比表(供逐行核对)

| 反作弊常见红线 | 本助手 | 备注 / 风险点 |
|---|---|---|
| 读取/修改游戏内存 | **否** | DXGI 只读屏幕,不碰进程内存 |
| 进程/DLL 注入、hook 游戏渲染 | **否** | overlay 是独立窗口,不注入 |
| 模拟/自动化输入(自动施法、脚本) | **否** | 零输入,只显示信息 |
| 抓屏 / 截图本身 | **允许(业界共识)** | OBS/直播/截图工具均在用 |
| 全局键盘/鼠标钩子 `SetWindowsHookEx` | **目前否** | ⚠️ 若将来加热键,优先 Electron `globalShortcut`,**避免全局钩子**(VAC 可能误判) |
| 修改/篡改目标游戏窗口 Style/ExStyle | **否(硬红线)** | 见 §2.4、§3 |
| 修改游戏文件/客户端 | **否** | 不动游戏任何文件 |
| 提供"游戏内得不到的信息优势" | **灰色地带 ⚠️** | **政策判断,非技术判断**——即便技术干净,Valve 仍可能从竞技公平角度限制此类工具。须以官方条款为准 |

---

## 5. 两个必须诚实声明的不确定点

1. **技术合规 ≠ 政策允许**。VAC 主要查"注入/内存/篡改"等技术特征,本助手在这层很干净;但用户协议/竞技规则可能从"公平性"角度限制"提供游戏内得不到优势的第三方工具"——只有官方条款能回答。
2. **检测面客观存在**。DXGI 截屏、koffi 加载 user32、置顶覆盖窗口在系统层面可见;VAC 通常不扫这些(否则误伤 OBS/Discord),但取决于 Valve 实现,无法保证。
